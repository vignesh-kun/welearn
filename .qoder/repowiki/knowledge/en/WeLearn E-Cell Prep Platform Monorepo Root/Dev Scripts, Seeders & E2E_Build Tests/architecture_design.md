Two sibling folders with distinct roles:

- `scripts/` — standalone Node/TS executables invoked directly (via bun or node) against a live Prisma-managed database. They split into four categories: (1) **seeders** (`seed.ts`, `seed-words.ts`) that upsert curated content via `@prisma/client`; (2) **migration tooling** (`migrate-sqlite-to-supabase.ts` reads `prisma/db/custom.db` through `node:sqlite`'s `DatabaseSync`, emits an idempotent SQL seed plus optional live Prisma upsert; `generate-align-sql.ts` writes a full PostgreSQL schema + foreign-key DDL into `supabase/migrations/20261107_init_postgresql.sql`); (3) **E2E smoke tests** (`arena-smoke.mjs`, `e2e-restructure.mjs`) that drive the running Next.js API at `http://localhost:3000` via `fetch` across multi-stage Arena lifecycles, Video Zone peer-quizzes, Founder Cases, PPT Challenges, PIN gates and Leaderboard assertions; (4) **utility/cleanup** (`arena-cleanup.mjs`, `copy-standalone.mjs`, `test-engine.ts`).

- `tests/` — pure POSIX shell scripts exercising `.zscripts/*` build helpers in isolated temp directories. `database-runtime-build.sh` mocks `bun db:push` to assert preview-vs-production DB handling; `python-runtime-build.sh` asserts Python artifact packaging; `python-runtime-container.sh` additionally runs the produced artifact inside a Docker image (`RUNNER_IMAGE=z-ai-python-deploy-runner:test`) to verify dependency isolation.

Dependency direction is one-way: scripts import from `src/lib/*` only for shared seed data and the crossword engine; tests never import application code and instead assert on filesystem artifacts under `$BUILD_DIR`.
