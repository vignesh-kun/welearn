The root is a private Next.js 16 + React 19 application whose `src/app` layout (app_shell) renders the authenticated UI, while the database model lives in a separate Prisma schema (database_schema) that generates the client via `postinstall: prisma generate`. Cross-cutting wiring is centralized here: `next.config.ts` disables strict mode and ignores build errors for Vercel; `tsconfig.json` maps `@/*` to `./src/*`; `components.json` configures shadcn/ui's New York style with aliases (`@/components`, `@/lib`, `@/hooks`, `@/components/ui`). The `scripts_and_tests` child exposes Node/TS utilities (`scripts/migrate-sqlite-to-supabase.ts`, `scripts/seed.ts`) invoked through npm scripts like `db:migrate-all` and `db:seed`, bridging the app shell's runtime against the Prisma-generated client. Deployment targets are declared at this level via `vercel.json` (Vercel) and `Caddyfile` (self-hosted Docker standalone output).
