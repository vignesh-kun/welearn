Two complementary layers coexist under this module:
- `prisma/schema.prisma` is the single source of truth for the domain model, declaring ~25 models (User, Puzzle, CaseStudy, Term, QuizTrack/Question/Attempt/Badge, PitchAttempt, GDSession/GdRoom/GdParticipant/GdRating, CaseVideo/VideoWatch/VideoQuizQuestion/Answer, FounderCaseQuestion/Answer/AnswerRating, PptChallenge/PptUpload/PptRating, Word/WordProgress/WordLog, Crossword/CrosswordWord/CrosswordSolve, MemoryProfile) with relations, indexes, defaults and JSON columns. The datasource points at PostgreSQL (`provider = "postgresql"`) using `DATABASE_URL` / `DIRECT_URL` env vars, and generates a `prisma-client-js` client.
- `supabase/migrations/` holds timestamped SQL migration files (`20261107_init_postgresql.sql`, `20261107_init_schema.sql`, `20261107_data_seed.sql`) that mirror the Prisma model as raw DDL against the `public` schema; these are consumed by the Supabase CLI (`supabase db push` / `supabase db reset`).
- `supabase/config.toml` configures the local Supabase stack: Postgres 17 on port 54322, API on 54321, Studio on 54323, Realtime, Auth (email enabled, SMS disabled), Edge Runtime (Deno 2), Storage (50 MiB limit, S3 protocol enabled), Analytics backend postgres, and pg-delta as the diff engine. Migrations and seed are both enabled.
Dependency direction: Prisma schema → generated client used by the app; Supabase migrations are derived from the same model and run independently against the local Postgres instance.
