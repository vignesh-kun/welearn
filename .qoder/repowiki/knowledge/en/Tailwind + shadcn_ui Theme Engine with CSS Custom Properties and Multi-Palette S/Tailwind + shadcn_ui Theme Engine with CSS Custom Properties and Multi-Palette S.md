## Approach

The WeLearn frontend uses **Next.js App Router** styled entirely with **Tailwind CSS v4** (`@import "tailwindcss"` in `src/app/globals.css`, PostCSS plugin `@tailwindcss/postcss`). The component library is **shadcn/ui** (configured via `components.json` with `style: "new-york"`, `rsc: true`, `tsx: true`, `iconLibrary: "lucide"`, aliases mapping `@/components/ui` → `./src/components/ui`). Animation support comes from the `tailwindcss-animate` plugin plus the `tw-animate-css` package imported alongside Tailwind.

Theming is built on **CSS custom properties** scoped to `[data-theme="..."]` selectors rather than relying solely on Tailwind's dark mode. The `darkMode: "class"` setting in `tailwind.config.ts` is kept for legacy `.dark` class toggling, but the primary mechanism is a `data-theme` attribute applied to `<html>` by the runtime theme engine.

## Key Files

- `tailwind.config.ts` — extends Tailwind's default color palette to map every semantic token (`background`, `foreground`, `card`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, `chart-*`) to CSS variables like `hsl(var(--primary))`; also maps `borderRadius.lg/md/sm` to `var(--radius)`.
- `src/app/globals.css` — single source of truth for all design tokens and styles. Imports Tailwind and `tw-animate-css`, declares an `@theme inline` block that re-exposes CSS variables as Tailwind theme values (e.g. `--color-primary: var(--primary)`), then defines ten complete palettes under `[data-theme=...]` selectors, followed by shared utility classes (`.glass-card`, `.tile-logo`, `.morph-hover`, `.shimmer`, `.flip-card`, `.crossword-cell`, `.reels-scroll`, etc.) and a `prefers-reduced-motion` media query that disables animations.
- `src/lib/themes.ts` — client-side theme engine exposing `THEMES` array of 10 VS Code-grade palettes, `applyTheme(id)` which sets `document.documentElement.dataset.theme` and toggles the `.dark` class, and `storedTheme()` reading/writing `localStorage` key `welearn.theme.v2`.
- `components.json` — shadcn/ui configuration pointing at `src/app/globals.css` as the CSS entry, using CSS variables and neutral base color.
- `postcss.config.mjs` — registers only `@tailwindcss/postcss`.
- `src/components/theme-provider.tsx` — React provider that bootstraps the theme on mount.
- `src/components/welearn/theme-switcher.tsx` — UI for switching between the 10 themes.

## Architecture and Conventions

1. **Design-token layer**: Every color is consumed through CSS variables (`--background`, `--foreground`, `--primary`, `--card`, `--sidebar-*`, `--chart-1..5`, `--radius`). Components never reference hex or HSL literals directly; they use Tailwind utilities like `bg-background text-foreground` which resolve to those variables.

2. **Palette system**: Ten palettes are defined in `globals.css`, each implementing the full set of variables. They follow VS Code-inspired naming: `dark-plus` (default), `light-plus`, `pink-moon`, `yellow-nitro`, `dracula`, `monokai-pro`, `one-dark`, `abyss`, `synthwave-84`, `everglades`. Each palette sets `color-scheme: light|dark` so browser-native elements (scrollbars, selects) adapt automatically.

3. **Runtime application**: `themes.ts` is the single source of truth for available palettes and persistence. `applyTheme` writes the chosen id to `document.documentElement.dataset.theme` and toggles `.dark` for any code still keyed off the Tailwind dark-mode class. The current selection is persisted under `localStorage.welearn.theme.v2`.

4. **Component library**: All reusable primitives live under `src/components/ui/` (accordion, alert, button, dialog, table, toast, sidebar, etc.), generated by shadcn/ui and styled with Tailwind utility classes. Business logic components live under `src/components/welearn/` (arena, crosswords, auth-screen, app-shell, home-view, quiz-view, etc.).

5. **Animation strategy**: Shared motion primitives live in `globals.css` (`.aurora-blob`, `.conic-halo`, `.shimmer`, `.float-idle`, `.heart-beat`, `.xp-sheen`, `.timer-urgent`, `.flip-card`, `.crossword-cell`). These are composed with Tailwind utilities rather than being encapsulated as separate animation packages. A `prefers-reduced-motion: reduce` block globally disables these animations.

6. **Typography**: Fonts are referenced via CSS variables `--font-body` and `--font-display` (set elsewhere, likely in the layout file); sans-serif defaults to `ui-sans-serif, system-ui, sans-serif`, monospace to `ui-monospace, monospace`. Headings get tighter letter-spacing (`-0.02em`) than body text (`-0.006em`).

7. **Responsive strategy**: No custom breakpoints are declared in `tailwind.config.ts`; the project relies on Tailwind's default breakpoint scale. Mobile detection is handled via the `use-mobile.ts` hook.

## Conventions and Constraints

- **All colors go through CSS variables**: Palette definitions in `globals.css` declare the complete variable set per `[data-theme]`; Tailwind's `@theme inline` block re-exports them as `--color-*` so Tailwind can consume them. New palettes must define the same variable set.
- **New palette registration**: Add a `[data-theme="<id>"]` block in `globals.css` AND add a corresponding entry to the `THEMES` array in `src/lib/themes.ts` (with `id`, `name`, `dark`, and `swatch` triple).
- **Dark mode toggle**: Use `applyTheme` from `themes.ts` rather than manually toggling `.dark`; it keeps `data-theme` and localStorage in sync.
- **Reduced motion respected**: Any new animation should be covered by the existing `prefers-reduced-motion` block in `globals.css`.
- **shadcn/ui components**: Generated components under `src/components/ui/` are treated as immutable primitives; customization happens via Tailwind class composition, not by editing the component files.
- **No SCSS/Sass**: The project uses plain CSS with Tailwind directives; there is no Sass pipeline configured.
